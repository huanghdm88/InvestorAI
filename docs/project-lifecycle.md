# 项目阶段与角色场景

前三阶段由投资经理负责，进入尽调后投委会开始参与。极光智算默认位于投决，保留接触、入库、立项和尽调的回看入口。新增记录是明确标识的本地演示快照，不冒充真实客户、联系人、审批或预算。

| 阶段 | 决策问题 | 必要记录 | 完成动作 |
| --- | --- | --- | --- |
| 接触 | 是否值得继续投入了解 | 来源、联系人、负责人、首访、产品与客户概况、初筛、缺口与跟进结果 | 确认进入入库 |
| 入库 | 是否具备可检索的项目档案并有人跟进 | 主体及档案编号、赛道/基金匹配、去重、负责人、资料版本、完整性与缺口处置 | 确认进入立项 |
| 立项 | 是否批准尽调资源 | 评审结论、投资假设、四类尽调范围及交付物、人员、时间预算、准入条件 | 开始尽调 |
| 尽调 | 当前事实能否支持待验证的投资假设 | 最近变化、问题与依据、推演、项目数据、初版投决报告 | 人工确认变化、补充证据 |
| 已投决 | 正式决议如何落实、是否出现重大变化 | 决议、获批方案、条件、责任与期限、建议去向 | 核验落实、提交授权复核 |
| 已签协议 | 签署版是否偏离方案、交割条件是否满足 | 条款对照、签署版本、先决条件、权利义务 | 补齐交割证明 |
| 已出资 | 实际交易结果是否一致 | 实际付款、名册持股、方案对照、归档缺口、投后基线 | 确认基线与投后交接 |
| 投后 | 实际经营相对基线发生了什么 | 最新经营、偏差、现金期限、治理、融资退出事项 | 跟踪与重大事项判断 |

投资经理查看执行全量信息与责任安排；投委会查看共享依据、关键条件和需要审议的重大变化。委员不参与前三阶段，也不显示日常执行工具。每个阶段的快捷指令在底部输入框中生成草稿，发送后形成绑定阶段快照的历史产物。

## 当前阶段与回看

`Project.currentLifecycleStage` 保存实际阶段，`lifecycleStage` 保存当前查看阶段，`completedLifecycleStages` 只包含已完成的阶段。查看历史只切换 `lifecycleStage`；完成当前工作通过独立的 `onAdvanceStage` 推进。阶段轨迹始终保留返回实际当前阶段的入口。历史记录只读，当前早期阶段可以编辑记录；内容通过 `earlyStageRecords` 保存在当前浏览器中，刷新后恢复。

接触到入库、入库到立项、立项到尽调是逐阶段推进。投委会尽调前没有操作模块。只有真实进入尽调才产生阶段通知，回看历史、切换项目或切换视角不会再次通知。

投委会页头的通知入口显示未读数量；通知可筛选、标读或直接打开项目。打开历史尽调通知时展示项目实际当前阶段，即使项目已进入投决也不会倒退。通知和已读状态在当前浏览器持久化，这是站内演示流程，未接入跨用户推送服务。

极光智算增加独立的签约、出资、投后情景选择器。`previewProjectStage` 仅改变查看阶段，不改 `currentLifecycleStage`、决议条件或通知；刷新恢复实际进度。后三阶段使用明确标注的独立交易假设：投前 11.8 亿元、本轮 1.2 亿元、投后 13 亿元、我方 3,000 万元与持股 2.3077%。这组值不回填当前决议中尚未知的融资与投资金额。投后继承出资情景的实际付款、名册持股和权利基线，不使用拟投资额或未落地融资意向。

对话按 `ownerRole` 隔离，未标明归属的旧演示对话归投资经理。草稿、报告选择、分析版本与采纳记录按角色、项目和阶段隔离；共享资料与正式工作流仍共用。运行任务保留提交时的角色、阶段和材料快照，切换角色不会串用任务结果。本地角色切换只是演示边界，未实现服务端用户鉴权。

## 默认信息展示

投资逻辑与融资用途、项目与市场仅在尽调和投决显示，并默认展开。两角色的项目依据默认展开，按钮固定为“项目依据”；投委会使用质询问题与重大变化模块。最近变化默认收起并显示数量，人工采纳不会自动改写共享事实。早期阶段只显示当时的记录和阶段依据；后三阶段使用交易与经营数据，不复用尽调估值栏。阶段名称后的完成小点已移除。

## 验证

`node scripts/verify-early-stages.mjs` 校验默认投决场景完整性、角色隔离、历史只读、返回当前阶段、已保存字段、未知项目空值和默认展开。阶段推进与通知另由 App/生命周期合同脚本验证，浏览器验证覆盖编辑、保存、推进及响应式布局。
